# 寄存器压力 pass 的 A/B

通过 `bazel run //:llvm_benchmark_ci -- --reports-dir /path/to/reports` 运行 Linux CI 的基准组合。
Rust 配对基准及其构建日志保存在 `ab-*` 子目录，zstd 解码、doubleFast 和 FSE 回放的配对结果分别写入
`decode/results.json`、`double-fast/results.json` 和 `fse/results.json`。单独运行 `//:llvm_benchmark_compare` 的
`pair` 模式时，可使用 `--output FILE` 同时保存终端中的 JSON 结果。

## ABI 与私有栈对象

在同一 Linux x86-64 主机上使用 rustc 1.100.0、LLVM 23.1.5。真实 Rust ABI 微基准由三个切片、一个标志、一个整数步进参数组成。两组均经 rustc fat LTO，LLVM IR 中保留了 Rust 生成的 `captures(none)`、`noalias` 和切片长度范围。压力 pass 在这组 A/B 中关闭，仅切换本地 ABI 模块。

| 热循环单次调用的栈访存 | 原 ABI | RegCall |
| --- | ---: | ---: |
| 调用者写入溢出参数 | 2 | 0 |
| 被调函数读取入栈参数 | 2 | 0 |
| 调用者读取自身的 spill slot | 3 | 4 |
| 合计 | 7 | 4 |

调用点充足活跃、占去一个非易失参数寄存器正是模型中的代价项。汇编证实消除了两次 push 和一次栈指针回收，同时调用者多一次 reload。在 LLVM 的 `rssn-call-abi-report` 中，RustFFT 有 28 个已通过签名过滤的候选，全部由于间接、可见性或其他调用边界约束保留原 ABI。RustFFT 整体压力 pass 的优化汇编与上一版 A/B 的优化汇编逐字节相同。

私有栈对象的机器码验证覆盖一个 `captures(none)` 初始化调用与一个无法取得该对象地址的 opaque 调用。结果由 1 次 spill 和 1 次 reload 变成 0/0，同时保留对原栈对象的单次读取。缺少捕获约束、指针已存入全局、opaque 调用直接收到地址、对象生命周期结束和 `llvm.localescape` 的用例均拒绝该改写。

每组 11 对样本轮流执行 A/B 或 B/A，固定逻辑 CPU 3。ABI 热调用每个样本执行 6,000 万次。每对输出哈希一致。负值表示耗时减少。

| 内核 | 配对耗时变化 | 95% bootstrap 区间 |
| --- | ---: | ---: |
| Rust ABI 热调用 | -13.60% | [-18.54%, +5.68%] |
| 可延后的 SIMD 读取 | -22.98% | [-24.89%, -22.14%] |
| 回调改写输入的标量读取 | -2.84% | [-8.08%, -0.80%] |

ABI 耗时区间跨过零，所以此次确认的是热路径栈访存减少。RustFFT 九个尺寸在本轮的耗时区间也都跨过零。现有 RSSN 二进制用于验证瓶颈分类，未重编 RSSN 整库做 release A/B。

## 联合规划与读取融合

2026-11-26，Linux x86-64、Intel Core i5-7300U、rustc 1.100.0 和 LLVM 23.1.5。对照组和优化组使用相同的优化器和后端。计时及 RustFFT 符号统计沿用下文的实验口径，基线已重新构建。

| 工作负载 | 对照 spill / reload | 优化 spill / reload |
| --- | ---: | ---: |
| 可跨调用延后的 12 个向量 | 12 / 12 | 0 / 0 |
| 共享地址和 GP 活跃值的联合移动，宽度 1 对宽度 4 | 2 / 2 | 0 / 0 |
| 回调会改写输入的两个相邻标量 lane | 2 / 2 | 1 / 1 |
| RustFFT 6.4.1 的全部 RustFFT 符号 | 4,105 / 6,265 | 4,092 / 6,241 |

联合移动用同一插件消融。宽度 1 时，两个 SIMD 载入留在调用之前。宽度 4 时，单个计划同时移动两个载入和一个整数定义，SIMD 跨调用活跃值从 2 变成 0。该用例通过了 `llc` 指令注释复核。

读后回调的测试要用调用前的两个标量做计算。对照组为两个 8 字节 spill 和两个 folded reload。优化组在回调前做一次 128 位读取，保留一个 16 字节 spill，回调后用带 16 字节 folded reload 的 `vmulpd`。这减少了栈访问指令数，传输字节数相同。独立 extract 的早期实现会被 SelectionDAG 拆回原先的两次读取。相邻标量组当前要求相容的向量算术，回归测试同时验证 IR 形状和后端 spill 数。已有向量消费者的直接 pack/concat 用例会融合 IR 读取，这两个测试在当前 x86 后端的机器码原本就能收敛到单读取。

RustFFT 的 244 个分析记录中有 78 个函数发生改写。158 个联合计划覆盖 526 次移动。这一版的静态 spill 少了 13 条，reload 少了 24 条，静态计数范围包括未被这些尺寸调用的函数。RustFFT 样本没有触发宽读取融合，因此读取融合的收益来自独立的正反例，不能从 RustFFT 的统计中归因。

每项测量使用固定逻辑 CPU 3、11 对交替 A/B 和 B/A 进程，所有输出哈希一致。负值表示耗时减少。95% 区间通过对配对比值重抽样得到。

| 输入 | 配对耗时变化 | 95% 区间 |
| --- | ---: | ---: |
| 可延后读取的向量内核 | -22.63% | [-23.54%, -15.38%] |
| 回调改写输入的标量内核 | -1.63% | [-3.69%, +0.35%] |
| RustFFT 12 | +0.70% | [-2.77%, +6.48%] |
| RustFFT 18 | -1.87% | [-2.56%, -1.03%] |
| RustFFT 27 | +0.59% | [-15.93%, +2.82%] |
| RustFFT 64 | +2.09% | [-3.87%, +9.77%] |
| RustFFT 120 | +0.35% | [-8.77%, +7.94%] |
| RustFFT 256 | -0.78% | [-5.50%, +6.89%] |
| RustFFT 512 | -6.71% | [-19.89%, +11.85%] |
| RustFFT 704 | +0.86% | [-8.66%, +8.83%] |
| RustFFT 4096 | +3.53% | [-0.60%, +40.34%] |

两个受控内核都确认了后端访存指令的减少。标量内核的耗时区间跨过零。RustFFT 的静态变动小，耗时表现随长度变化，只有 18 点用例的区间在本轮完全低于零。Linux 主机同时有其他工作，硬件计数器在当前权限下不可用。RSSN 整库仍没有 release A/B。

## 第一版基线记录

2026-11-26，Intel Core i5-7300U，Linux x86-64，固定逻辑 CPU 3。RSSN 插件与 rustc 1.100.0 携带的 LLVM 23.1.5 一起运行。RustFFT 对照组加载同一插件并关闭 pass。回调内核使用匹配版本的 `opt` 和 `llc`，两组由同一份 O3 IR 生成。编译均用 `target-cpu=native` 或工具对应的 `-mcpu=native`。

### 回调后的向量内核

内核载入 12 个四路双精度向量，再调用一个返回缩放系数的 C ABI 函数。优化前，12 个向量都跨调用活跃。将 load 及其短地址计算移到调用之后，保留了 12 次输入读取。后端把它们折叠到以输入地址为操作数的 `vmulpd`。

| 度量 | 对照组 | 优化组 |
| --- | ---: | ---: |
| 跨调用活跃 SIMD 值 | 12 | 0 |
| 机器码 spill | 12 | 0 |
| 机器码 reload（含 folded） | 12 | 0 |
| 链接后反汇编中以 `%rsp` 为基址的显式访存 | 24 | 0 |

在两组链接后的 ELF 中用 `objdump -d --disassemble=rssn_callback_kernel` 复核。对照组有 384 字节的向量 spill 区，两组都仍有调用约定所需的寄存器保存指令。

### RustFFT 6.4.1

使用 RustFFT 的默认 planner 和 `process_immutable_with_scratch` 处理预分配批次，规划和初始化在计时前完成。统计范围为最终链接产物中 `7rustfft` 符号片段匹配的函数。244 个有分析记录的函数中有 69 个发生改写，其中有 374 次块内纯定义下沉、136 次延后 load 和 4 次跨块放置。这套已优化的 IR 没有触发重复 load 合并，其改写和屏障行为由 IR 回归测试覆盖。

| 静态机器码计数 | 对照组 | 优化组 |
| --- | ---: | ---: |
| Spill | 4,105 | 4,098 |
| Reload（含 folded） | 6,265 | 6,254 |

IR 诊断和机器码可以按函数对照。实测部分内核的 spill/reload 增加，例如 AVX 的 27 点蝶形内部例程从 15/16 变成 17/19，部分内核减少，例如 12 点蝶形的 immutable 路径从 4/4 降到 3/3。

### 耗时和限制

用 11 对独立进程交替运行 A/B 与 B/A。百分比取每对 `优化耗时 / 对照耗时 − 1` 的中位数，区间为对配对比值重抽样的 95% bootstrap 区间。负值表示耗时减少。每个样本都对完整输出求位级哈希，所有 A/B 对照一致。

| 输入 | 配对耗时变化 | 95% 区间 |
| --- | ---: | ---: |
| 回调向量内核 | -20.37% | [-27.25%, -14.04%] |
| RustFFT 12 | +1.13% | [-0.23%, +4.28%] |
| RustFFT 18 | +0.09% | [-5.90%, +5.53%] |
| RustFFT 27 | +3.27% | [-4.09%, +19.32%] |
| RustFFT 64 | -4.14% | [-22.49%, +6.78%] |
| RustFFT 120 | +29.69% | [-8.69%, +78.17%] |
| RustFFT 256 | -5.50% | [-15.92%, +2.28%] |
| RustFFT 512 | +20.55% | [+0.67%, +28.45%] |
| RustFFT 704 | +3.06% | [-6.03%, +25.04%] |
| RustFFT 4096 | -7.53% | [-13.26%, +4.23%] |

对 512 点单独复测，A/B 为 +7.76%（95% 区间 [−16.96%, +15.27%]），同一基线二进制的 A/A 为 +2.94%（[−3.09%, +10.86%]）。全套跑分中的 +20.55% 未在复测中稳定重现。机器运行着其他任务，且当前权限没有开放硬件性能计数器。RustFFT 的全二进制静态计数不能代替热路径的动态 spill 次数。此次完整 A/B 使用 RustFFT 替代 RSSN 的长编译，RSSN release 的性能收益仍待实测。
