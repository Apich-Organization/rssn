# The contract the bindings rely on

Everything in `python/`, `julia/`, `cpp/` and `r/` is written against the C ABI in
`rssn.h` (generated by cbindgen from `src/ffi/`) plus the kernel manifest. This
file records the parts of that contract a wrapper depends on, so a change to the
ABI that would break a binding is visible in one place.

The authoritative descriptions are `src/ffi/mod.rs` (the ABI's own "limitations
and coverage" section), `docs/KERNEL.md` and `docs/DIMENSIONS.md`.

## Handles and lifetimes

| Rule | Consequence in the bindings |
|---|---|
| `rssn_session_new` / `rssn_config_new` return heap objects freed with `rssn_*_free` | RAII: Python `__del__`/context manager, Julia `finalizer`/`close`, C++ destructor, R external pointer finalizer |
| Terms are `uint32_t` indices owned by one session, valid until the session is freed | A term keeps its session alive; a term from another session is refused before the call |
| `RSSN_NO_TERM` (`UINT32_MAX`) means a failed constructor | Becomes an exception with a status hint (`Parse` for text, `UnknownOperator` for `apply`) |
| Strings and byte buffers are caller-owned, released with `rssn_string_free` / `rssn_bytes_free` | Every read goes through one helper that frees the exact pointer it read |
| `RssnTensor` owns `shape` and `data`, released with `rssn_tensor_free` | Copied out, then freed, in a `finally`/`defer`-equivalent |

## Statuses

`RssnStatus` is the whole error vocabulary and it is coarse: every
`ComputeError` maps to one code, the boundary errors have their own, and the
message is for humans. The bindings therefore:

- raise with the code attached (`RssnError.status`, `RssnError.status`,
  `Error::status()`, the R condition's `$status`), and never parse the message;
  the one exception is R's `call_value`, which reads the "argument N has type
  ..., expected ..." wording to retry with the other numeric kind, because R has
  no integer literal;
- read `rssn_last_error()` immediately after a failure, because it is
  thread-local and is not cleared by a later success;
- treat the shortcut entry points (`rssn_simplify`, the four renderers, the term
  constructors) as failing when they return `RSSN_NO_TERM`/null, and attach the
  status the attempted operation implies.

## Ordering inside a computation

`rssn_compute` fills `RssnAnswer` and records the thread's dimension findings.
`rssn_dimension` **runs the request again** and re-records them, so a wrapper
that wants both reads `rssn_dimension_count`/`rssn_dimension_code` first. The
session's answer cache makes the second run a hit, so the cost is not doubled.

## Threads

A session is single-threaded (`RefCell` inside). The bindings give each thread
or task its own default session and expose `compute_all` for parallel requests
inside one session. The per-thread error message and the per-thread dimension
report are why a session must not be shared even when the host is single-minded
about locking.

## The two ABIs

| ABI | Entry points | Carries |
|---|---|---|
| term | `rssn_term_apply`, `rssn_compute`, `rssn_compute_all`, the renderers | `uint32_t` handles to graph nodes |
| value | `rssn_value_*` | session-owned *cells*, each holding one `Value` |

A value crosses as a `uint32_t` cell id (`0` is never valid), is owned by the
session that minted it, and is released with `rssn_value_free` or with the
session. `rssn_value_call` runs an operator on cells — that is
`Session::call_value`, so an operator with a dynamic evaluator is run by it and
every other operator is built into a term and reduced. `rssn_value_to_term`
turns a value into a term when the value has a graph form.

Cells are the only way to carry what the term graph cannot hold: a native
object handle (`Value::Opaque`, which is how AD tapes, compiled backends and
solver handles travel), a record, a sparse tensor. `rssn_value_json` serialises
any value for a host that would rather parse than branch.

## Reachability

`KernelManifest.backend_support.ffi` is the engine's own statement about whether
an operator can be called through this ABI: `rssn_term_apply` when its arguments
are terms, `rssn_value_call` when they are values, and `rssn_callback_new*` for
the function arguments of a higher-order operator. It is `true` for all 5411
operators; the generated facades keep every name and route the 189
higher-order ones through the value ABI.

## Host callbacks

A higher-order operator takes a `Value::Function`, which is a handle into the
calling context's callback bank. The C ABI gives a host three ways to fill that
bank:

| Entry point | Signature source |
|---|---|
| `rssn_callback_new_for(session, op, index, fn, user, out)` | the operator's declared function parameter at `index` |
| `rssn_callback_new(session, signature_json, fn, user, out)` | explicit `{"params": [...], "ret": ...}` |
| `rssn_callback_signatures(session, op, index, out)` | lists what `op` accepts at `index` |

The bank lives in the session (`RssnSession::callbacks`), and
`rssn_value_call` copies it into the `CallCtx` it runs with, so a callback cell
is usable as an argument for as long as the registration is live.
`rssn_callback_free` retires a registration and leaves a reusable slot, so a
host that builds a closure per iteration does not grow the bank.

A declared signature that mentions a dimension variable (`Real[D]`) is
instantiated as dimensionless before it is handed to the host: a C callback sees
plain numbers and tensors of them, which is what the engine passes it anyway.

Inside a callback the arguments are live cells owned by rssn, so a host must not
free them; the result cell it writes to `*out` becomes the engine's. The
callback runs on the thread that entered the computation and the engine does not
call it in parallel.

## What the wrappers add

Nothing that the engine does not already say:

- the operator facade is generated from the manifest, so it cannot invent an
  operator, an arity or a signature;
- the value ABI is a thin mapping of `Session::call_value` and the `Value`
  accessors: it adds no semantics of its own;
- the units, constants and dimension text come from the manifest;
- the scenario catalog is scanned from `src/sim/scenario*.rs` because the
  manifest does not carry it and the ABI has no entry point that lists them;
- the JSON codecs are the host languages' own (`json` in Python, a 200-line
  codec in Julia, raw text in C++), applied to records the engine serialises.
